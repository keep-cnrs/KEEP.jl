KEEP functions used by the paper

The docstrings of the main functions of KEEP.jl called by main.jl.

KEEP.PointMass4

KEEP.PointMass4.dynamics — Function

Compute du, the evolution of the state — closed-form implementation (default).

Same model as _dynamics_verified, with the explicit formulas of applications/jtcam/scratch/pm2-model-derivation-reworked.tex instead of six ForwardDiff calls per evaluation: 2.33× cheaper per evaluation, 2.1× on a limit-cycle solve, identical to the verified version to 1e-15 (test/04a, run by verify_fast_rhs.jl in the benchmark).

u = (α, τ, dα, dτ) du = (dα, dτ, ddα, ddτ)

KEEP.PointMass4._accelerations_tension — Function

Accelerations and line tension from the kinematics k, the external force F = F_a + F_g on the kite, the generator torque and $\dot R$. Returns (ddα, ddτ, Fℓ).

The three unknowns satisfy the projections of Newton's law for the kite on $\hat r$ and $\hat r'$ (the tangent plane of the cone), and the arm balance $I\ddot\alpha = a\lambda F_\ell - \text{torque}$, where $a\lambda = a\,\hat\ell\cdot(\hat z\times\hat a)$ is the lever arm of the lines. It vanishes on the fold curves $\alpha = \varphi, \varphi + \pi$, so the arm balance is solved for $\ddot\alpha$ (dividing by $I > 0$), never for $F_\ell$: the remaining $2\times 2$ system in $(\ddot\tau, F_\ell)$ has determinant $-m r \|\hat r'\|^2 R/\ell - m R r_\tau^2/(r\ell) - m^2 a^2 \ell r \|\hat r'\|^2\lambda^2/(I R) < 0$ everywhere, so the vector field and the tension are smooth on the whole state space.

KEEP.PointMass4.compute_line_tension — Function

[For post-processing]

Given u and p, compute the line tension Fℓ (N), exact everywhere, including on the fold curves where the lever arm of the lines vanishes (see _accelerations_tension).

KEEP.LimitCycle

KEEP.LimitCycle.compute_limit_cycle — Function

Compute a limite cycle by integrating from u0.

The shooting obtained by settling is refined by refine_shooting unless refine = false.

Return its shooting parameters [α0, dα0, dτ0, T].

Compute the attracting limit cycle with sense(dτ) > 0, by integrating from the Poincaré-section state u0 = (α, τ, dα, dτ) = (0, TAU0, 0, sense(1)).

Both pumping cycles are attracting, so the sign of dτ selects one and the magnitude of the seed only needs to be a reasonable guess. Use all_limit_cycles for an inventory of every cycle in a box; the two calls are independent.

KEEP.LimitCycle.refine_shooting — Function
refine_shooting(shooting, vbp; sense, tol, maxiter=8, target=tol / 100)

Refine shooting = [α0, dα0, dτ0, T] by Newton's method on the closure residual endpoint_residuals(shoot(shooting)) (4 equations, 4 unknowns, Jacobian by ForwardDiff through the integrator), with a backtracking line search on the max norm of the residual. Stop below target, after maxiter iterations, or when no step decreases the residual.

Settling by integration converges only linearly to the cycle, and stops on the distance between two successive crossings, not on the distance to the cycle: the shooting it gives closes up to an error that depends on the contraction rate and on floating-point details. Newton converges quadratically from it, so the refined cycle closes at the level of the integration tolerance (issue #79).

Return (shooting, residual). The refined shooting is only kept if it decreases the residual, keeps the sign of dτ0 and has T > 0; otherwise the input is returned, so that refining never makes a cycle worse.

KEEP.LimitCycle.all_limit_cycles — Function

Comptue all limit cycles by sampling N initial conditions within a region of the Poincarré section.

  • A rough integration with low precision (sqrt(tol))
  • Clusterize and take centroids
  • Integrate each centroid with high precision (tol)

KEEP.Optimization

KEEP.Optimization.optimize — Function

Performs optimization to find optimal limit cycle parameters using Ipopt.

Arguments

  • p: An initial VBPara (physical units) used to establish base parameters and characteristic dimensions.
  • optim_para_syms: A vector of Symbols for the VBPara parameters that will be optimized.
  • optim_para_lower: A vector of Float64 specifying the lower bounds for the optim_para_syms in their physical units.
  • optim_para_upper: A vector of Float64 specifying the upper bounds for the optim_para_syms in their physical units.
  • sense: + for rising on the sides of the lemniscate, - for kite dropping on the sides
  • tol: Absolute/relative tolerance for the ODE solver. The dynamics inside the non-linear constraints is integrated at tol / 10, and Ipopt is called with tolerance tol.
  • max_wall_time: Maximum wall-clock time in seconds for the Ipopt solver.
  • max_iter: Maximum number of Ipopt iterations (nothing, the default, keeps Ipopt's own limit). Unlike max_wall_time it does not depend on the machine, so results are reproducible. Ignored by solver=:madnlp.
  • linear_solver: The linear solver to use for the Ipopt solver, cf. https://coin-or.github.io/Ipopt/OPTIONS.html#OPTLinearSolver. Defaults to "mumps".
  • solver: :ipopt (default) or :madnlp; the latter needs using MadNLP (KEEP ships it as a package extension, so Ipopt-only users pay nothing).
  • hessian: :exact (default) uses the exact Hessian. :lbfgs uses a limited-memory quasi-Newton Hessian — cheaper per iteration but it wanders on bad starts, so it retries with the exact Hessian when the cheap attempt fails or throws. :auto leaves the solver default (exact). On the whole paper.jl the exact Hessian is 1.9x faster (154 s against 287 s), because failed L-BFGS attempts dominate the sweeps.
  • rhs: :auto (default, the closed-form PointMass4.dynamics) or :verified (the AD reference _dynamics_verified). :fast/:ad are accepted as aliases.
  • symmetry: exploit the invariance S(α,τ,dα,dτ) = (-α, τ+π, -dα, dτ) and integrate only half a period, imposing x(tf) = S x(0). Returns the full period in tf. Faster, but fragile: the symmetric formulation has more than one stationary point and a seed a fraction off the symmetric manifold can settle on the wrong one (measured: 4.2 kW against 12.25 kW). Check the returned power before trusting it.
  • initial_guess: A NamedTuple, Dict, or ComponentArray specifying initial starting values in physical units. This can partially or fully overwrite the baseline limit cycle guess. Because it accepts and returns physical dimensions, the returned solution can be passed directly into this argument for iterative refinements. Defaults to an empty NamedTuple (;).

Returns

  • solution: A ComponentArray containing the optimized variables (states, time, power, and optimized parameters) mapped to their physical dimensions.
  • stats: The statistics object from the Ipopt solver.
  • model: The ADNLPModel object used for the optimization.

Notes

The optimization is performed in a normalized (dimensionless) space to improve solver conditioning. The optim_para_lower, optim_para_upper, and initial_guess inputs are expected in physical units and are converted to normalized units internally. While the raw stats.solution remains in normalized units, the returned solution ComponentArray is automatically scaled back to physical units.

KEEP.PointMassPara

KEEP.PointMassPara.optimal_torque_slope — Function
optimal_torque_slope(p = build_para(); sense = +, tol = 1e-3, maxiter = 5, rtol = 1e-4)

Torque slope b that satisfies the kinetic criterion b = I ω, with ω the angular frequency of the limit cycle (ω = 2π/period, period in seconds from a simulation). The period depends on b, so the value is a fixed point: solve the cycle, set b = I 2π/period, solve again until b stops moving. Returns b in the units of p.b and prints nothing.

p0 = build_para()
p0.b = optimal_torque_slope(p0)
vbp = build_vbpara(p0)

The limit cycle solver lives in KEEP.LimitCycle, which is included after this module, hence the runtime lookup.
